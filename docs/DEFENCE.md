## Three résumé bullets

- Built an offline USGS backfill verifier that compared 2,569 events across independent whole-week and daily captures, killed a SQLite worker before commit and recovered all records with zero projected-field mismatches. [Integrated run](evidence/quake-verify.txt)
- Implemented immutable publication history and exercised four concurrent reader loops across a publisher crash. All 36 current reads matched their ID-specific reference digest, and both historical extracts remained retrievable. [Publisher drill](evidence/quake-publish.txt)
- Diagnosed a redundant 1,839,817-byte download after an acquisition crash. Persisted request-bound receipts and verified zero repeat requests for the intact body while completing all seven remaining daily requests. [Before and after](evidence/M07-orphan-remediation.txt)

## Twenty interview questions and model answers

1. **Who needs the publication ID?** An analyst can cite the exact membership and values of a report. An operator can advance current after recovery while that earlier report stays readable. [ADR-0001](adr/0001-catalog-structure.md)
2. **Why a separate whole-week request?** Concatenating daily results would repeat a daily acquisition mistake in the reference. The week came from its own HTTP response, and its parser projects directly from the original features. [ADR-0002](adr/0002-catalog-acquisition.md)
3. **Who owns midnight?** The new UTC day does. On the source's millisecond grid, the previous query ends at 23:59:59.999 inclusive. A boundary fault test used an actual event time. [Design](design/DESIGN-DOC.md) · [Boundary evidence](evidence/M07-failures.txt)
4. **What stops a truncated response becoming evidence?** The collector checks response shape, byte length when declared, feature count, warnings and the 20,000-result ceiling. It seals the manifest after reading back every expected body and checking its digest. [Collector](../earthquake/acquire.py)
5. **Why compare before deduplicating?** Replacing one daily record with another existing record preserved the 2,569-row total. Counting per-ID multiplicities exposed the duplicate and the anti-join exposed the missing ID. [Controlled M03 faults](evidence/M03-reconcile.txt)
6. **Can unchanged IDs conceal an error?** Yes. The independent comparison includes event time, update time and magnitude for shared IDs. A controlled magnitude change under the same ID failed. [Reconciler](../earthquake/reconcile.py) · [M03 evidence](evidence/M03-reconcile.txt)
7. **How do you distinguish drift from a restart bug?** Compare independently acquired bytes for source agreement first. Freeze both sides and replay the daily path through recovery for the second verdict. Preserve any disagreement and block publication. [ADR-0002](adr/0002-catalog-acquisition.md)
8. **What makes a skip safe?** A completion checkpoint identifies the fixture digest, day and body hash. The writer locks before checking it and commits the rows and checkpoint together. [Ingestion](../earthquake/ingest.py)
9. **How do you know the worker reached the intended instruction?** The worker signals the parent and blocks at the October 4 pre-commit barrier. The parent terminates that process, checks its exit and opens a new connection to inspect rows and checkpoints. [Worker control](../earthquake/restart.py)
10. **What if the worker dies after commit but before acknowledging it?** In the separate M04 case all 383 October 4 rows and their checkpoint were durable. Restart skipped the target and the final rows agreed with the reference. [M04 transcript](evidence/M04-restart.txt)
11. **Why can the shorter publication be complete?** Its declared scope ends at October 4 midnight. Every included day needs a checkpoint and its rows must match the week filtered to that interval. An omitted in-scope checkpoint blocks the publish. [History drill](evidence/M05-history.txt)
12. **What determines a publication ID?** SHA-256 covers deterministic metadata including scope, source provenance, row count and row digest. Ordered event IDs and canonical magnitudes make the returned-row encoding repeatable. [Publication code](../earthquake/history.py)
13. **Can a reader see half a publication?** Publication rows and the current pointer commit together. A reader selects the pointer and rows within one read transaction. M06 forced a writer exit between the pointer update and commit. [ADR-0003](adr/0003-catalog-storage.md)
14. **How do you detect a stale payload bearing the new label?** Hash the CLI's actual returned rows and compare to the independently expected digest for its reported ID. The controlled old-rows/new-label test exercises that mistake. [Reader check](../earthquake/publish_drill.py) · [Test](../earthquake/test_publish.py)
15. **Why publish two recovery times?** The 935.782 ms from kill includes the deliberate outage observation. Starting at retry gives 317.162 ms. Both end at the first verified new read in that M06 run. [Incident](postmortems/m06-publisher-crash.md)
16. **What exactly did the benchmark time?** Three repetitions per level, eight reads per loop after warm-up, spanning a normal publish. Latency included process launch, SQLite read, JSON transport and digest verification. The four-loop pooled p95 was 335.77 ms across 96 reads. [Protocol](benchmarks/m07-protocol.md) · [Measurements](benchmarks/README.md)
17. **Is 125.22 MiB a hard memory ceiling?** It was the largest sampled sum of Windows working sets across the harness and active CLI children. Shared pages may be counted twice and spikes between samples can be missed. [Memory measurements](benchmarks/README.md)
18. **Why did a correct orphan hash initially fail the drill?** After the raw rename, verified request metadata existed only in memory. Restart fetched the same intact whole response once, transferring another 1,839,817 bytes. The bandwidth requirement allowed zero. [Original failure](evidence/M07-failures.txt)
19. **How does restart now authenticate an orphan?** Before promotion, it installs a receipt binding acquisition, query, attempts, size and SHA-256. The same-run restart checked retained bytes, transferred zero whole bytes and fetched the outstanding daily bodies. Corruption failed closed and absent provenance required refetch. [Repair evidence](evidence/M07-orphan-remediation.txt)
20. **Where does the evidence stop?** One historical week on a local Windows volume, one writer, worker/publisher process termination and at most four measured reader loops. Power cuts, sustained overload and multi-host failover would require separate experiments. [Failure register](failure-register.md) · [Benchmark](benchmarks/README.md)
